## Prompt 19 — CLI generator Terraform fajlova

```text
Implement cli/internal/generator and the cf generate command.

Goal:
Generate readable Terraform root environment files from clusterforge.yaml.

Supported targets for first version:
1. aws + eks
2. aws + ecs

For environment:
cloud: aws
orchestrator: eks

Generate into env.path:
- versions.tf
- backend.tf
- providers.tf
- main.tf
- variables.tf
- outputs.tf
- terraform.tfvars.example
- README.md

For aws+eks:
main.tf must compose:
- modules/core/tags
- modules/cloud/aws/network
- modules/orchestrators/kubernetes/eks
- modules/platform/kubernetes/bootstrap optional as commented block

For aws+ecs:
main.tf must compose:
- modules/core/tags
- modules/cloud/aws/network
- modules/orchestrators/ecs/cluster

Rules:
- Do not overwrite files unless --force.
- Generated files must include a header:
  # Generated by ClusterForge. Safe to edit, but regeneration may overwrite with --force.
- Use relative module paths from environment directory to modules directory.
- Generate safe example CIDR values.
- Generate no real secrets.
- Keep generated HCL readable; do not minify.

Implementation options:
- Use Go text/template for now.
- Do not use complex HCL AST unless necessary.
- Put templates under cli/templates/env/aws-eks and cli/templates/env/aws-ecs.

cf generate <env> flags:
- --force
- --dry-run
- --orchestrator override optional
- --cloud override optional

Dry-run:
- Print which files would be created/updated.
- Do not write files.

Tests:
- Generate aws+eks into temp dir.
- Refuse overwrite without force.
- Dry-run writes nothing.
- Unknown target returns useful error.

Run:
- gofmt
- go test ./...
```
